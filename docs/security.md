# 安全与使用边界

本文说明使用者和部署者需要了解的权限、隐私及数据维护要求。漏洞报告方式见 [安全策略](../SECURITY.md)。

## 订单访问与隐私

- 订单查询密码以哈希保存；订单详情和卡密需要订单密码或所属会员账号授权，充值订单仅本人登录后可查。
- **邮箱查询不验证邮箱所有权。** 验证码通过后可返回关联商品订单的摘要，包括商品、金额、时间与状态。运营者应确认这一查询方式符合业务隐私要求。
- 订单访问凭证在有效期内不会随退出登录或账号改密立即撤销。不要分享凭证、完整查询链接或含有这些信息的日志。
- 浏览器会保存最近查询过的邮箱和临时订单凭证；使用共享设备后应清理邮箱历史并关闭会话。

## 登录、后台与反滥用

账号改密或封禁会撤销旧登录会话和此前签发的密码重置链接。管理员应使用独立强密码，按角色分配权限：OPERATOR 负责商品与发货，ADMIN 可管理用户和财务，SUPER_ADMIN 可修改系统设置及客服与社群配置。

验证码和频率限制用于缓解自动化滥用，不能代替身份验证。限流效果依赖可信客户端 IP；多人共用网络可能共用额度，分布式请求仍需运营侧防护。

## 支付、库存与通知

- 外部支付需同时配置有效凭据并启用通道。服务端核验付款信息，通过事务及唯一流水避免重复入账或发货；上线前应完成实际收款账户的小额联调。
- 未付款商品订单会占用库存并受待付额度限制，付款或取消后释放额度；余额即时购买和充值不占该额度。
- USDT 自动收款仅支持 TRC20。错误金额、过期付款及其他异常需人工核对，ERC20 自动收款未开放。
- 余额退款返还站内余额；外部支付退款需先在支付平台人工执行，后台只登记结果。
- 邮件与 Telegram 为可选通知，失败不影响已完成的入账或发货，也不保证自动补发。配置的通知服务可能接触订单信息或发货卡密，应限制接收人并保护服务凭据。
- 客服与群二维码属于公开展示内容。微信客服文字虽不在弹窗中显示，仍由公开接口返回，不应填写私密备注。维护方法见 [客服与社群说明](community/README.md)。

## 部署、密钥与数据保留

- 公网入口使用 HTTPS。默认 Nginx 只提供 HTTP；使用 Cloudflare 时应配置源站 TLS、Full (strict) 和源站访问限制。
- 应用、PostgreSQL 和 Redis 端口仅对可信网络开放。启用 `TRUST_PROXY=true` 前，确保代理覆盖客户端 IP 且访客不能直连应用；缺少可信 IP 时无法对不同访客分别限流。
- `NEXTAUTH_URL` 必须与实际访问的协议、域名和端口一致。保留应用的安全及缓存响应头，HTML 页面不得使用共享缓存。
- 使用独立随机密钥和管理员密码。不要提交 `.env`、真实卡密、凭据、数据库备份或运行日志。
- 卡密采用服务端加密，持有加密密钥的运营者可解密。限制密钥和备份访问；更换密钥前必须重新加密已有卡密。
- 更新前备份数据和配置。财务流水和已售卡密不会随取消订单清理自动删除，数据保留与销毁需另行制定。

## 验证与依赖维护

验证命令见 [贡献说明](../CONTRIBUTING.md)。测试通过覆盖已验证的路径，不代表不存在漏洞；当前文件和提交邮箱扫描也不能保证所有历史对象或托管平台副本已清理。

`braces` 的已知安全公告目前仍通过安装时的可校验补丁缓解，普通 `npm audit` 可能继续报告相关依赖。`npm run audit:security` 校验补丁并拒绝其他告警或联网失败；不要跳过安装脚本或降低整个审计阈值。上游修复可用后应验证升级并移除临时补丁。
