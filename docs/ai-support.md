# AI Shop 智能客服技术文档

## 1. 当前能力

商城提供全站悬浮“小AI同学”入口，首次打开新对话自动显示“您好，我是AIShop的智能客服小AI同学，请问有什么可以帮您？”。客服可以回答已发布知识库中的购买、商品、支付、发货、账户、售后和联系方式问题，并读取实时商品库存、价格、启用的支付方式、公告和已授权的本人订单摘要。

客服不会自动购买、付款、取消订单、退款、修改账户或显示卡密。需要人工处理时，查询已保存的微信客服/Telegram 配置；微信二维码以该条回答的图片附件显示并支持放大，不常驻聊天底部。商品详情和订单查询等跳转显示为回答中的站内按钮。原独立 `/help` 页面已经移除。

系统继续使用现有前台用户和后台管理员鉴权，不新增客服角色。后台知识和客服配置沿用现有管理员权限。

## 2. 数据边界

PostgreSQL 是知识正文和业务数据的唯一事实源。商品、库存、价格、支付和订单状态不写入向量索引，也不由模型记忆回答。客服模型只能使用本轮后端查询返回的事实。

`SupportArticle` 保存标准问题、别名、关键词、分类、正文、状态和发布版本。`DRAFT` 不会被检索，只有 `PUBLISHED` 进入线上回答。保存草稿和发布是轻量的两状态流程，不包含审核流或多人协作。

`SupportConversation`、`SupportTurn` 和 `SupportModelCall` 保存会话、脱敏问答、来源、实时事实摘要、调用阶段和用量。客服提问还保存账号关联、脱敏身份哈希、可信 IP 标记和请求编号，供授权管理员排查。游客 Cookie 与服务端恢复权限按最后有效访问滑动 24 小时，已过期会话不可续期复活；登录用户保持创建后 30 天的恢复期限。关闭弹框保留会话，前端不提供手动清除入口，客服会话 API 不支持 DELETE。问答、身份/IP 和风控明细按各条记录的创建时间默认保留 90 天，用量账本默认保留 180 天，两项可在后台配置。定时清理会先清除正文、来源、事实、身份/IP 和关联，保留用量账本；到达用量保留期后再清理模型调用明细。

订单查询遵循现有权限：登录用户只能查询本人订单；游客必须完成现有订单查询和密码解锁流程。订单密码、访问 token、卡密和管理员备注不会进入模型上下文。

## 3. Agent 与多轮上下文

每条问题先完成身份与会话校验、限流和请求去重。明显越界请求在服务端拒答，基本寒暄固定回复。六个固定常见问题及完整同义问法直接走已发布知识和当前业务查询，状态为 FAQ，不调用模型、不消耗模型 token；匹配要求整句一致，附加任务不进入此路径。其余请求在启用模型时由一次无工具规划请求同时判断范围并提出最多 4 个只读查询；服务端重新校验工具名称和参数，执行查询后再调用回答模型。规划和回答默认使用同一个当前模型，因此普通问题通常从三次模型请求减少为两次。规划输出上限 256 Token，回答输出上限 1,000 Token；单次上游请求超时 25 秒，整体处理 65 秒，包括规划在内最多 4 次模型请求和 8 次工具调用。规划失败、不确定或格式无效不执行工具，拒答、无法分类和未完成记录不进入后续上下文。读取按时间倒序取最新记录再按时间正序呈现，超过 20 轮也不会停在早期对话。摘要保留早期问题与当时回答片段，最多 6,000 字符；它只是上下文，不能作为当前库存或价格。超长会话仍可能需要用户再次确认早期细节。

模型自行选择只读工具，不由关键词预先指定业务链路：

| 工具 | 范围 |
|---|---|
| `search_products` | 当前上架商品及有效分类，返回精确名称匹配和相关商品、价格、库存、详情路径；最多 20 条并标记截断 |
| `search_knowledge` | 已发布知识，最多 4 条 |
| `get_payment_methods` | 当前启用且满足配置条件的支付方式 |
| `get_my_orders` | 服务端认证用户最近 5 条订单摘要，无 userId 参数；游客只获得登录/订单查询指引 |
| `get_contacts` | 当前公开客服设置 |
| `get_navigation` | 从商品目录、订单查询、本人订单、登录/注册、找回密码和余额/充值白名单选择页面；不接受任意 URL |
| `get_announcements` | 当前公开公告 |

每条非固定常见问题先进行 1 次规划（最多 256 输出 Token），规划必须包含服务端可校验的只读查询列表；通过后执行查询，再进行回答模型请求（最多 1,000 输出 Token）。包括规划在内总计最多 4 次模型请求、8 次工具调用，最后一轮禁止继续调用工具。单次上游请求超时 25 秒，模型循环总时限 65 秒。参数按严格白名单校验，工具没有任意 URL、SQL 或业务写入能力。Responses 保留 function_call 和必要 reasoning 项，Chat Completions 按 tool_call_id 回传结果。

未配置模型时仅提供有限的确定性知识/事实帮助；固定常见问题直接提供知识、库存/支付等当前事实和图片/导航，不受模型故障或预算耗尽影响；其他问题在范围分类故障时返回固定服务提示。分类通过后的回答网关失败也提供有限的知识/事实帮助；已配置模型的故障降级会提示智能回答暂不可用。工具查询失败返回 QUERY_FAILED，不能冒充空结果。每次实际模型调用均保存独立 token/状态记录，范围分类记录带 SCOPE_ 标识，工具资料和历史只能作数据，不可改变权限。

模型工具查询会接收本轮取消信号；取消或总时限触发时，通过独立的 PostgreSQL 取消连接池终止当前工具事务中的查询。取消连接池每个应用进程最多 2 个连接；查询使用事务内唯一标记，清理完成前保留客服并发名额。客服只读事务设置单语句 3 秒、锁等待 1 秒的数据库超时，取消通道不可用时仍有服务端兜底。商品、知识、本人订单、公告及缓存未命中的设置查询均适用；不带取消信号的普通设置读取和固定 FAQ 保持原有路径。这不保证模型供应商停止远端推理或停止计费。

## 3. 检索实现与迁移路线

第一阶段的 `searchSupportKnowledge` 使用 PostgreSQL 读取已发布条目，按标准问题、别名、关键词、分类和二字符片段进行召回，再由模型组织回答。标准问题及别名忽略标点匹配，完整别名优先于二字符片段；通用问法和单个汉字不参与召回。无模型配置时只展示最高相关条目的已发布正文，内部知识编号和来源不会拼入回答。库存与支付方式问题优先使用本轮事实；支付失败、退款、领取卡密不视为支付方式查询。“哪些商品有库存？”及完整同义问法仅列出商品和分类均上架且库存大于 0 的商品；过滤在数据库截取结果数量前执行，零库存/下架商品不生成跳转按钮，没有符合条件的商品时明确提示暂无有库存的上架商品。具体商品询价仍可说明该商品缺货。新提问读取当前库存，历史消息与同一 requestId 重试保留原回答，不自动刷新。

这不是永久排除向量检索。检索层应通过统一的 `KnowledgeRetriever` 接口调用，正文和版本仍由 PostgreSQL 管理，索引属于可重建派生数据。

迁移路线：

```text
阶段一：PostgreSQL 关键词/别名/相似字符串
    ↓ 评测召回率不足
阶段二：PostgreSQL + pgvector 混合召回
    ↓ 规模或并发继续增长
阶段三：PostgreSQL 事实源 + 独立向量库
```

阶段二为已发布条目生成 embedding，使用条目 ID、发布版本、内容哈希和模型版本关联。阶段三只把条目 ID、版本、embedding 和过滤元数据同步到 Qdrant、Milvus 等服务，正文、权限和发布状态仍由 PostgreSQL 控制。新索引先并行评测，再灰度读取，保留旧检索作为回退。

更换 embedding 模型时需要重建向量，但知识正文、版本、对话、用量和业务数据均可保留。pgvector 或独立向量库都不能替代实时业务查询。

## 4. LLM 与 sub2api

商城使用独立的 sub2api 凭据，不能复用 ChatGPT/Codex 桌面应用的 key。线上凭据仅在 `.deploy/production.env` 配置 `SUPPORT_LLM_API_KEY`（本地 `.env` 与自动化测试不读取它），前端和后台只显示是否已配置。开发/人工验收的 3013 可在 `.env` 单独配置专用模型凭据、网关地址与限额，开发进程和候选容器均会读取；自动化测试仍禁用外部模型，不能复制线上凭据。

```env
SUPPORT_LLM_PROVIDER=sub2api
SUPPORT_LLM_BASE_URL=http://host.docker.internal:8080/v1
SUPPORT_LLM_API_KEY=REPLACE_WITH_SUPPORT_GATEWAY_KEY
SUPPORT_LLM_MODEL=gpt-6-luna
SUPPORT_LLM_WIRE_API=responses
SUPPORT_DAILY_BUDGET_CNY=10
```

Docker 容器中的 `127.0.0.1` 指向容器自身；sub2api 在宿主机运行时应配置容器可达的地址，例如 Docker Desktop 的 `host.docker.internal`，Linux 部署按实际网络配置。上线前必须在商城容器内验证网关、模型、Responses 接口、工具调用和 usage 返回。

首选模型由真实客服评测决定。`gpt-6-luna` 是低成本候选，`gpt-5.4-mini` 用作质量对照；官方价格只是成本估算，sub2api 的映射和倍率以网关为准。没有 key、模型不可用、预算耗尽或网关错误时，自动降级为知识库和事实回答。

## 5. 请求和安全控制

- 每条消息最多 2,000 字符；请求体有字节上限。
- IP 和用户/游客身份受 Redis 限流；会话使用跨进程 Redis 锁，重叠请求返回 409。会话过期或自动清理后，迟到答案不能重新写入。
- 请求使用 `requestId` 去重，重复提交不会重复调用模型。
- 模型没有 SQL、任意 URL、用户身份或写业务数据的工具。
- 前台仅返回回答、turnId、状态及结构化 ui 图片/按钮，不返回知识来源、工具证据、内部摘要或 system prompt。来源与工具调用证据保存服务端。图片采用后台校验的 HTTPS 地址，按钮仅接受服务端站内白名单或有效商品路径；不渲染模型 HTML。UI 数据随历史与重试恢复，保留期自动清理时一并清理。
- 上游请求使用 `store: false`，Authorization 永不进入日志。
- 配置、模型和价格修改通过管理员后台；密钥轮换通过部署配置完成。

## 6. Token 与费用统计

每次实际上游调用记录请求模型、响应模型、输入 token、缓存读取、缓存写入、输出 token、推理 token、总 token、耗时、成功状态和估算费用。工具调用后的再次请求、失败请求和重试分别记录。

```text
普通输入 = 总输入 - 缓存读取 - 缓存写入
费用 = 普通输入 × 输入单价
      + 缓存读取 × 缓存单价
      + 缓存写入 × 写入单价
      + 输出 × 输出单价
```

推理 token 已包含在输出 token 中，不重复计费。usage 缺失时标记 `MISSING`，不能按零费用统计。后台提供调用次数、输入/输出/缓存/推理 token、估算美元、失败次数和缺失 usage 数量。

默认每日预算为 10 元人民币，后台「配置」还可管理数据保留期和游客/会员提问限额。预算按上海时区自然日计算；每次上游请求前在数据库事务中原子预占预算，完成后按 usage 结算；缺失 usage 或进程中断保留保守占用，达到预算后不再发起新的模型请求，但知识库和人工入口继续可用。费率和汇率只在服务端使用并随调用保存快照，不在后台开放。游客/会员每日额度默认50/200次、每60秒窗口默认5/10次，在「配置」中调整；已用次数不会因保存而重置，已有冷却仍会持续到期。身份/IP/全站并发、单IP每日500次、重复问题冷却和熔断仍由代码控制；这些安全上限仍可能先于身份额度触发。管理员通过风控页面临时封禁或解封。

## 7. 管理后台

`/admin/support` 包含四个标签：

- **知识库**：新建、编辑、保存草稿和发布；维护标准问题、相似问法、关键词、分类和正文。
- **Token 统计**：按时间分页查看模型调用、token 分项、成本、usage 缺失、耗时，以及脱敏问题、答案、账号、可信 IP 和调用阶段；不再限制最近 500 次。
- **账号隐私**：账号字段由服务端默认脱敏（如 `al***@example.com`），完整账号仍可搜索。仅超级管理员可点击单条记录的眼睛图标请求原文，再次点击隐藏；更改筛选、翻页、切换标签或刷新后恢复隐藏。查看接口不缓存，成功返回前写入风控审计（管理员ID、问答ID、时间，不含账号原文），每管理员每分钟最多30次；游客、已清理或超过当前明细保留期的记录不可查看。此开关只管理账号字段，不隐藏问答正文或IP。
- **查看审计详情**：风控排查中的“查看完整账号”事件整行可点击，右侧箭头表示可查看；列表展示管理员账号、问题、脱敏账号和可信 IP，不展示内部管理员 ID 或问答 ID。点击后切换到 Token 统计，按内部 ID 精确加载并展开对应问答；不受当前分页和最近7天筛选影响，但仍受当前明细保留期和清理状态限制。
- **风控排查**：查看限流/冷却事件，按账号、身份哈希或可信 IP 创建临时客服封禁并解除。
- **配置**：显示当前模型、网关和 key 配置状态，可调整每日预算、问答和身份/IP 明细保留天数（默认90天）、用量记录保留天数（默认180天）、游客/会员每日模型提问上限（默认50/200）和每分钟上限（默认5/10）。页面同时只读展示代码固定的规划/回答 Token 上限（256/1,000）、请求/总时限（25/65秒）、模型轮数/工具调用（4/8）、身份/IP/全站并发（1/3/8）及重复问题冷却（60秒内重复4次，冷却15分钟）。

读取端同时按保留期过滤统计、风控和会话，调用账本中的超期关联问答清除正文及身份/IP；不依赖定时清理先完成。配置保存与清理使用同一事务锁，预算修改与预占也共用日预算锁。

配置保存采用事务并记录审计，清理设置缓存；模型提问准入与清理任务直接读取当前策略，读取失败时不使用旧缓存或默认策略放行/删除。明细保留期为1–365天，用量保留期为1–730天且不能短于明细；日额度为1–10,000次，分钟额度为1–1,000次。缩短保留期在下一轮定时清理时删除超期数据，延长不能恢复已清理数据。统计日期范围最多730天。

发布后的知识立即进入检索，草稿不会影响线上客服。动态商品、库存、支付和订单信息始终由业务服务实时读取。固定常见问题直接查询已发布知识和实时事实，其余自由提问进入模型理解与工具调用循环；商品、价格、库存、支付、订单、客服配置由工具按需读取。Redis 设置缓存会在后台保存后清理，但已生成的历史客服消息不会改写，重新提问才会使用最新配置。

## 8. 验收与运维

上线前应验证：

1. 匿名咨询、登录用户本人订单、游客订单密码解锁和充值订单权限。
2. 停售商品、零库存、支付开关、订单状态和客服配置变化能够反映到答案。
3. 草稿不可见，发布可见，旧版本和索引可回退。
4. sub2api 不可用、usage 缺失、超时、限流和预算耗尽均能降级。
5. 模型不会看到密码、卡密、Authorization、内部备注或其他用户数据。
6. 重复 requestId、并发消息、提示注入和恶意 URL 不产生越权或重复扣费。

提交前运行项目既有门禁：

```bash
npm run db:generate
npm test
npm run build
npm run test:integration
npm run test:http
npm run check:secrets
npm run check:history
npm run audit:security
```
