# AIShop 客服工具优化

日期：2026-11-08（Asia/Shanghai）

## 结果

本轮按 Anthropic《Writing effective tools for agents》的工具设计原则，完成客服工具契约、商品分页筛选、知识原文续读、工具错误信息和证据记录优化。代码在本地开发环境生效，未发布公网。

## 主要改动

- 统一 `src/lib/support/tool-contract.ts`：工具名称、严格参数、默认值、价格边界和错误类型由同一份契约生成和校验。
- `search_products` 在数据库侧先应用名称、价格和库存条件，再进行名称优先排序和分页；每页保留完整商品描述，返回 `nextOffset`。
- `search_knowledge` 返回已发布知识的连续正文片段、版本和游标；新增 `read_knowledge_article`，每次读取重新验证发布状态和版本，避免用旧政策回答。
- `src/lib/support/llm.ts` 记录每次工具调用的缓存命中、字节数、估算Token、耗时、截断和错误；版本变化会清除同轮旧知识搜索缓存。
- 服务端同时保存原始工具结果和模型实际收到的结果；按钮只由成功交付的商品生成。
- 新增 `npm run support:eval`，支持固定基线、合成题集、保留题、结果哈希和持久费用预占账本。

## 真实模型评测

真实评测使用开发专用模型配置、合成商品/知识资料、固定基线和总费用上限 CNY 1。工具用途问题首次发现模型只检索通用知识，补充契约后再次运行，模型改为查询商品描述并正确回答 Cursor 用途。

候选结果已实际覆盖预算推荐、价格库存、型号区分、退款人工边界、游客订单、激活故障、混合请求、知识干扰和多轮预算记忆。首次运行在历史多轮 M02 的基线侧遇到上游超时，之后在稳定网关下按失败重试继续完成。最终66对全部完成：候选66/66通过独立场景预期；基线仅H03因旧工具循环达到8次上限，候选通过分页和完整商品描述完成同一对比。H03基线失败作为对照结果保留，不能算候选回归。当前账本统计和原始转录在 `.deploy/support-tools-20261108/evaluation-ledger.json` 与 `.deploy/support-tools-20261108/eval-complete/`，质量复核在`quality-review.json`。已结算估算CNY 0.47587930，未知预占CNY 0.1075455，均低于CNY 1上限。
