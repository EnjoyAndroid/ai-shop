# 智能客服真实模型对照评测

日期：2026-11-05，Asia/Shanghai。结论：保留新版上下文与摘要方向，但范围规划仍会误判合法追问，价格变化话术有稳定回退，暂不能据此宣称全部场景稳定通过或直接发布。

## 测试条件与口径

- 真实模型 `gpt-6-luna`，Responses 协议，使用本地3013评测API和开发专用网关；所有商品、订单及政策均为 `synthetic-shop-v1` 合成资料，不代表真实商城业务。
- 旧版冻结自 `d16f4fccd8feb53f15e624440bee0e04dfb32efa`；新版为本次评测开始时的工作区。模型链、提示词、上下文、工具、限制和夹具文件哈希从开始到结束完全一致；未边测边改业务代码。
- 完整版本模式比较提示词、工具说明、上下文及输出上限的总体效果。提示词模式共用相同近期历史、工具和预算，仅更换系统指令。双方默认采样设置相同，模型仍有随机性。
- 19个独立问题完成有效测试；另完成10轮连续对话、8轮预置历史后追加7问的跨窗口测试，以及12个复测/提示词对照问题，共48对有效结果、96条回应。独立问题每题首次有效结果单列，复测没有混入独立问题分数。
- 评分由本次助手按提前定义的事实/边界/记忆标准复核，带主观判断，不是独立人工盲评。A/B映射由服务端随机，最终按实际版本汇总。
- 其中2道越界问题由服务端确定性拦截、0次模型调用，不用于证明提示词改善。按用户补充的业务验收规则，订单查询免登录，R10及复测重新评分；工具资料歧义作为根因线索，不免除回答错误。用户进一步确认R11按原“模拟商品查询故障”场景验收，两版均通过，保留现有行为。

逐题问题、预期、两版完整回复、判定理由及调用指标见[逐题记录](2026-11-05-support-live-evaluation-transcripts.md)。

后续开发以[智能客服优化最终方案](../plans/2026-11-05-support-final-plan.md)为准；该方案纳入用户最后确认的R11无需修改和订单查询免登录规则。

## 仍需修复的问题

1. **合法商城追问可能被范围规划误拒。** `P17b` 中双方收到相同完整商城历史，新版却将“我后来把预算改成多少了？主要用途是什么？”判为OUT_OF_SCOPE；完整版本记忆题表现较好不能抹去该反例。建议明确允许回顾用户已给出的商城选购条件，在规划阶段区分“没有商城上下文”与“问题是对已有条件的追问”；不要通过默认allow或跳过范围校验修复。
2. **把状态变化说成自己先前答错。** `R09/T09a/T09b` 新版三次均声称“之前说错/不准确”，实际证据只表明当前价格和库存已变。建议默认说明“当前查询为…，之前信息可能已变化”，只有确有证据才认定之前答错。
3. **检索标签外露并干扰推荐。** `S01/R02/M02.1` 等回复把名称的exactMatches/relatedProducts关系解释成“没有符合预算和用途的商品”，一边推荐99元套餐一边说不匹配。问题源于商品名称匹配和推荐条件满足混在一起；应仅在用户点名具体型号而未找到时说明指定型号未匹配，泛化选购则直接按返回资料筛选预算与用途。
4. **订单查询免登录，不能被引导为必须登录。** `/order`是公共查询页，`/orders`是需登录的本人订单页。R10及T10a新版要求先登录，按业务规则判未通过；T10b“登录/验证”混写判部分通过，旧版三次通过。M02.5新版只给“我的订单”判部分通过，原先以“测试身份”为由给满分缺少本轮证据。合成和真实工具的 `requiresLogin:true` 与“可以通过公共订单页解锁”并存，容易误导模型，应区分工具身份限制与页面访问条件。
5. **部分调用与呈现仍可精简。** 新版在仅回忆排除商品的题中额外查询了库存价格；多处输出Markdown粗体，而评测页按纯文本显示。正式客服已有清理逻辑，评测链没有完全复用显示处理，所以样式问题不能直接归因于模型质量。

本轮仅测试和记录，未实施上述业务修复；保持本次结果可以追溯到同一版本。

## 网关故障与无效结果

初批首题成功，随后两条规划请求返回429、再有50条规划请求返回503；这些52条故障回应不计提示词质量。多轮首批所有10问都未形成有效回答，因此整条链作废，恢复后另建 `M02` 从头测试。

首批脚本只检查HTTP外层是否成功，未将评测结果里的上游错误作为停止条件，继续发出无效请求；这是本轮评测执行的缺陷。已修正为遇到429、5xx、网络失败或超时立即停批，正常配对间隔10秒；保留初批数据，未隐去失败。网关恢复后的有效批次未再出现429/503。

最初网关日志读取曾因自动审批服务自身503未执行；后续只读汇总重试成功。没有重启网关、换模型、改账户额度或绕过限流。此处没有足够证据把上游429的具体原因归为并发、日限额或账号失效。

## 产物与后续

本机权威证据目录：`.deploy/support-live-evaluation-20261105/`。

- `manifest.json`：模型、协议、夹具版本、初始预算及冻结源码哈希。
- `*-plan.json`：预先定义的问题和预期；`*-result.json`：API原始结果与揭晓映射。
- `ratings.json`：每题人工复核；`metrics.json`：全部调用/故障/预算；`effective-metrics.json`：有效成对统计。
- `run.mjs`：可接续的测试入口，具备总额限制和上游故障停批；`checkpoint.json`：最终完成状态。

建议下一轮只修复上述范围规划、价格变化和工具语义问题，再复测失败题及保护反例。不要基于本次小样本自动发布公网。本轮没有业务代码修改、提交、推送或生产部署。
